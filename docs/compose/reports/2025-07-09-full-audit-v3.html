CRITICAL — 需要立即修复

▶CRITICALElectron shell.openExternal 无 URL 验证 — 协议注入electron/main.ts:134-136

证据

mainWindow.webContents.setWindowOpenHandler(({ url }) => {
    shell.openExternal(url);  // 无协议过滤，任意 URL 被打开
    return { action: 'deny' };
});

影响

XSS 构造的 smb:// URL 可窃取 NTLM 哈希，file:// 可打开本地文件，自定义协议可触发任意应用。这是 Electron 已知 CVE 类别。

修复：仅允许 https:/http: 协议。
▶CRITICALPandoc 路径由管理员控制 — subprocess 命令注入export.py:49,68,72

证据

pandoc = settings.pandoc_path  # 管理员可通过 PUT /api/settings 设置为任意值
cmd = [pandoc, str(tex_path), "-o", str(out_path)]
result = subprocess.run(cmd, ...)

影响

管理员可将 pandoc_path 设为 /bin/sh，用户请求导出时该可执行文件被调用，实现完全 RCE。

修复：使用 shutil.which() 验证路径指向真实 pandoc/xelatex，或限制可执行文件目录。
▶CRITICALdangerouslySetInnerHTML 未经消毒的 KaTeX 输出FormulaWorkspace.tsx:579

证据

dangerouslySetInnerHTML={{ __html: sanitizeKatexHtml(preview.html) }}

注：虽然已调用 sanitizeKatexHtml，但需确认该函数是否使用 DOMPurify 或等效方案。如果 sanitizeKatexHtml 仅做简单的字符串替换而非真正的 HTML 消毒，则 XSS 风险仍存在。

影响

如果 sanitizeKatexHtml 不够严格，恶意 LaTeX 可注入任意 HTML/JS。

修复：确认 sanitizeKatexHtml 使用 DOMPurify。若未使用，引入 DOMPurify 替代。
