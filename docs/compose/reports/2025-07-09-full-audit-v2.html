▶CRITICALElectron shell.openExternal 无 URL 验证 — 协议注入 RCEelectron/main.ts:134-136

证据

mainWindow.webContents.setWindowOpenHandler(({ url }) => {
    shell.openExternal(url);  // 无协议过滤
    return { action: 'deny' };
});

影响

任意渲染器注入或 XSS 构造的 URL（file://、javascript:、smb://）会被 OS shell 打开。smb: URL 可窃取 NTLM 哈希，file: 可打开本地文件，自定义协议可触发任意应用启动。

修复：仅允许 https:/http: 协议。
▶CRITICALPandoc 路径由管理员控制 — 命令注入 RCEexport.py:49,68,72

证据

pandoc = settings.pandoc_path  # 管理员可通过 PUT /api/settings 设置
cmd = [pandoc, str(tex_path), "-o", str(out_path)]
result = subprocess.run(cmd, ...)

影响

管理员可将 pandoc_path 设为 /bin/sh 或任意可执行文件。当用户请求导出时，该可执行文件被 subprocess.run 调用，实现完全 RCE。

修复：使用 shutil.which() 验证可执行文件路径，或限制可执行文件目录白名单。

▶CRITICAL文件上传先全量读入内存再校验大小 — OOM DoSpdf.py:25-28, ocr.py:107-108

▶CRITICALAdmin Token 确定性生成 — 可伪造settings.py:17-18,71-72

证据

def _make_token(password: str, session_id: str) -> str:
    return hmac.HMAC(password.encode(), session_id.encode(), hashlib.sha256).hexdigest()
# session_id 来自客户端头，攻击者可控制

影响

Token 由 (password, session_id) 确定性生成。攻击者知道密码后可伪造任意 session_id 的 token。相同 session_id 的多次登录产生相同 token。

修复：使用 secrets.token_urlsafe(32) 生成随机 token。

证据

// ComputePanel.tsx:100-103

修复：引入 DOMPurify 消毒所有 KaTeX 输出。

总结

整体风险等级：CRITICAL

本次审计覆盖后端 Python（16 个文件）、前端 React（19 个文件）、Electron（3 个文件）、Docker + 构建配置，共发现 78 个问题：7 个 CRITICAL、22 个 HIGH、27 个 MEDIUM、22 个 LOW。

最优先修复的 5 个问题：

  • Electron shell.openExternal 无验证（electron/main.ts:134） — 可被利用窃取 NTLM 哈希或执行任意应用
  • Pandoc 路径 RCE（export.py:49） — 管理员可设任意可执行文件路径
  • 文件上传 OOM（pdf.py:25, ocr.py:107） — 远程匿名 DoS
  • XSS via dangerouslySetInnerHTML（FormulaWorkspace.tsx:572） — 需 DOMPurify
  • .env 打包进 Electron（electron-builder.yml:12） — 密钥随应用分发

结论：代码不能直接上线。7 个 CRITICAL 漏洞涉及 RCE、XSS、DoS 和权限提升。建议按 CRITICAL → HIGH 顺序分批修复，每批完成后回归测试。Electron 相关问题（协议注入、环境泄露、跨平台兼容）需要特别关注。
